## 1. 地支不是缩小版天干

地支首先占据一个时令、方位、场景和容器位置，并在其中保存一层或多层人元。天干偏向单一而可见的发用接口，地支偏向复合场与待用资源；这一区别不能压成“天干能做事、地支不能做事”。

地支卡只解释已经审计的状态，不自行判断藏干是否透清、会局是否成立、冲是否开库、某气是否成为格用或某条路线是否真正起效。

## 2. 四层显化模型

每次处理地支，分别回答以下四个问题：

| 层 | 核心问题 | 允许的结构状态 | 不得偷换成 |
|---|---|---|---|
| `场在 field` | 这个支提供怎样的季节、空间、动静、容器与生活场景？ | `field-present`，并继承 retained／concentrated／redirected／damaged 等关系后修正 | 藏干已经直接做功 |
| `气在 qi` | 支中哪些人元仍保留库存、根气或环境供给？ | stock／root-support／environmental-feed／pattern-eligible／timing-only | 未透便不存在，或存在便等量可用 |
| `用起 function` | 哪个藏干或支局获准成为实际功能节点？ | direct-action gate、实际 edge、通量、承接与竞争均有收据 | 透出／会局便自动得用 |
| `果显 result` | 该场或功能是否已接到本题的现实载体与外部结果？ | topic axis、carrier bridge、现实承载与结果条件另行通过 | 有作用便已有外部成果或事件 |

四层是诊断分栏，不是机械的单一路径。可能出现：

- `场 → 载体`：问居住、工作环境或身体场景时，地支场本身可以进入现实表达，不要求某藏干先变成明干；
- `气 → 扶持 → 他节点发用`：藏干只作根气或环境供给，却通过被扶持的天干间接影响结果；
- `气 → 直接功能 → 载体／结果`：藏干获 direct-action gate，并沿实际路线到达领域体；
- `气在而用未起`：保留为库存、私下机制或待时条件，没有当前外部结果。

## 3. 显化依据必须成束

不得把任何单项写成自动开关。Structure Core 至少合看：

- 月令、司令、本气／中气／余气及季节支持；
- 同气或该藏干是否透出，以及透出节点是否仍可用；
- 柱位、远近、同柱关系和实际承接者；
- 重根、同气聚集或经 Branch Arbitration 裁定的会局／合局状态；
- 空亡、冲刑害破、合绊、占用、改道与共享节点竞争；
- 下游是否存在合法 edge、接收能力、去处与出口；
- 原局状态和岁运触发是否被分开。

因此：

- `透清`提高可见接口或发用资格的证据权重，但透而受制、被占、无承接时仍可能不起结果；
- 经裁定的会局可以聚拢、发动或改道，也可能只集中到另一方向；不得写成“见会便全部藏干发动”；
- 不透的得令本气、近身根气或成势之气，仍可能提供实质支持，证据充分时也可获得直接做功资格；
- 冲只提供关系后变化证据，不负责自动开库、释放藏干或把 hidden 改成 visible。

## 4. 没有外显结果时怎样表达

`果显`未通过不等于整支无效。按实际收据选择一个或多个并存模式：

- `field-background`：主要体现为环境、季节、场所、氛围或事情发生的容器；
- `stock-root-support`：作为库存、根气或承载，增强另一节点而不单独出面；
- `environmental-feed`：持续提供同气背景或局势供给；
- `internal-latent`：作用停留在内部、私下、准备态或尚未取得现实载体；
- `direct-function`：已经形成实际功能，但可见成果仍需另过结果门；
- `timing-pending`：原局保留接口，待特定岁运或场域条件补齐；
- `externalized-result`：只有载体桥接与结果条件均通过后使用。

这些模式不是吉凶标签，也不按“越外显越高级”排序。

## 5. 后天激活接口

原局的 `hidden／latent／timing-pending` 描述当前状态，不是“永远不透”。每个待时藏干可由 Structure Core 预登记 activation interface，至少说明：

- 原局当前怎样参与；
- 哪类透清、会动、补齐或关系场节点可触发重算；
- 命中后须从哪一阶段重新裁 branch／node／edge／route condition；
- 哪些功能只是 projected candidates；
- 哪些受制、占用、无承接或问题中心不调用的条件仍会阻止它。

岁运或另一人的干支进入时，只在冻结原局外建立 overlay。匹配接口后先标 `matched-pending-requalification`，重算通过才可写 `active-overlay`。它可能在时间窗内持续、间歇、短促，或仅绑定某段关系；不能预设一定渐进，也不能预设一定突然。

`natal_visibility` 始终保留原值，`overlay_visibility` 只说明本轮接口状态。关系结束或时间窗过去，临时差分失效；原局不被改写。对方盘有同字／同五行只提供候选接口，必须另有双方冻结、跨盘关系与本题相关性，不能自动激活。

## 6. 单支卡的职责

十二张单支卡负责展开：

1. 该支在季节循环中的位置与基本场景；
2. 五行、阴阳、方位、形态、动静与容器性质；
3. 本气／中气／余气可提供的分层候选，但不重算藏干事实；
4. 关系后状态怎样改写场景和候选载体；
5. 七条 Topic axes 与不同显化模式下的表达；
6. 哪些内容只是共同符号候选，哪些来自八字原典或课程扩展。

静态藏干与月令人元司令是两份不同事实：前者由 Reader 的藏干表登记集合与 `qi_rank`，后者由带节气偏移、采用口径和表源的 `month_command` 登记气序。单支卡必须同时保留二者，但不得以司令顺序增删藏干、改写本／中／余，也不得因某一气透清或被流年激活而把同支全部藏气一并发动。来源有异表时，只在 Source Receipt 登记分歧并服从 Reader 的框架锁。

单支卡不得自行宣布某藏干已透清、会局已发动、墓库已开、某气已成为用神，或某外部事件已经发生。每次调用必须引用 `branch_manifestation_receipt`。

## 8. Forward-test questions

1. 模型能否保留不透藏干的库存／根气，而不擅自给它直接作用边？
2. 模型能否区分“透清提高发用资格”与“透出即得用”？
3. 模型能否在地支场本身就是领域载体时给出明确表达，而不强迫藏干先外透？
4. 模型能否把直接功能与外部成果分开，不因前者成立便宣布事件已兑现？
5. 模型能否把会局的发动、集中与改道分开，并继承 Branch Arbitration 的实际裁决？
6. 模型能否保留“以后透清时会怎样”的重算接口，同时不把它写成当前事实？
7. 模型能否在岁运／合盘命中后重算受影响作用边，而不是只翻转 active 开关或回写原局？
