# 领域载体推导 v2.0

## 总原则

十神、干支和路线描述的是功能与运作方式，不直接等于一个行业、事件或身份。先把结构翻译成性质，再找现实载体。

现实载体不是禁词。形貌、行业、物件或人物角色只要与结构、状态和问题中心完成桥接，就可以明确列为较可能表达；禁止的是不做桥接便写成唯一事实。

具体职业、岗位、正式身份与事件属于 L5 `composite_domain_carrier`。单一天干、地支或十神 Deep Card 不能独立把 L5 升到 `supported`；但它已经激活的 L2 性质、L3 动作／材料和 L4 家族候选必须参加竞争，不能因无法证明具体职业而被过滤。卡片中的行业／角色例子须经过本文件的推导和载体竞争才能进入 finding。

## 两套层级不得混用

`specificity_level` 说明结论具体到哪里：

1. `L1-outcome-level`：学历、专业化、权责、收入等现实层级；
2. `L2-domain-nature`：技术型、制度型、经营型、研究型等性质；
3. `L3-action-material`：精密、器械、切割、修复、审查等动作材料；
4. `L4-carrier-family`：医疗、工程、制造、金融、法律等家族；
5. `L5-exact-identity-event`：具体职业、学校、正式身份或事件。

`claim_rank` 说明证据强度：candidate／supported／preferred／assertable。L5 需要更高桥接门槛，但 L1–L3 只要完整 process、十神链与干支柱位组合支持，即应作有方向的 `supported／preferred` 判断。不得因为 L5 只能 candidate，就把 L1–L3 也降成“无法判断”。

timing／synastry 中再加一道“关系功能先于人物身份”门：外来或被引动的十神先说明它在本 topic 中增强了哪种共享、竞争、权责、支持或交换功能，再按柱位／关系场、可见接口与命主当时位置比较人物候选。例如事业场的比劫可候选同事、同级合作者、竞争者或共享资源参与者；不得一律定为同事，更不得直跳小人、口舌或夺财事件。

## 五层现实推导

### 1. 内部操作

写清命主在处理什么：接收、筛选、研究、校订、表达、组织、竞争、照料、控制、转化、交易或承担压力。

### 2. 对象与素材

写清操作对象：隐蔽信息、规则、数字、语言、身体、关系、资金、审美素材、复杂案例、危机或公共注意力。

### 3. 工作条件

至少判断：

- 独立／协作；
- 稳定／项目制；
- 深钻／快速迭代；
- 规则密集／自由探索；
- 前台可见／后台专业；
- 短反馈／长战线；
- 低容错／高试验空间。

### 4. 输出与收益

分开：

- 产出形式；
- 是否被看见；
- 是否得到职位或器重；
- 是否形成收入；
- 收入来自工资、项目、交易、流量还是资产；
- 名声、资源和现金是否为同一条路线。

### 5. 现实例子

按以下顺序给例子：

1. `direct fit`：性质大部分同时成立；
2. `adjacent fit`：只承载其中一部分；
3. `role fit`：行业普通，但岗位内容吻合；
4. `channel fit`：社交媒体、创作或社群只是可见度渠道，不自动等于职业和收入。

行业例子先列最多三个 L4 家族并排序，再说明可能承载这些性质的岗位。没有 L5 门槛时，不写成唯一职业结论；但不得只列一串不排序的“都可能”。

若多个独立锚点都支持同一载体，可把它列为 `preferred` 并先说结论，再补例子。若没有真实竞争证据，不要机械写“但也可能不是”；改判条件只在确实存在时说明。

## 载体桥接收据

每个进入 finding 的现实载体至少记录：

1. `core_process`：底层运行性质；
2. `chart_anchor`：对应柱、节点、边或路线；
3. `post_relation_state`：当前支持、受压、改道或未显化状态；
4. `topic_axis`：为什么本题调用这个载体；
5. `carrier_rank`：candidate／supported／preferred／assertable；
6. `alternative_carriers`：若存在，为什么不优先。
7. `specificity_level`：当前到底在断层级、性质、动作、家族还是具体身份；
8. `lower_level_verdicts_preserved`：高层未通过时，已经成立的低层断语仍被保留。

## 反例

- “偏印适合玄学”缺少素材、操作、载体与现实条件，不合格。
- “有财就能赚钱”混淆资源、可见度和变现，不合格。
- “食神所以适合餐饮”从标签直跳行业，不合格。
- “七杀代表压力，因此只能做高压工作”忽略制化与承载条件，不合格。

## 领导与教育的专项 gate 示例

### 领导／管理角色

至少检查：

- career-work 领域轴确实在问组织权责、管理或岗位角色；
- 官杀、印、比劫、食伤等实际关系功能由本盘路线裁定，而不是由“甲为十干之首”预选；
- 权责路线端点、竞争占用与日主承载／调用权成立；“身强”不是唯一机械门槛；
- 相关节点有适当位置、可见接口、持续性和现实组织场景；
- 已比较正式领导、项目负责人、专业权威、资格／机构岗位等替代载体。

以上通过后，甲的发动、领起或主干性质只能为已成立角色着色；不能反向证明领导身份。

### 教育行业／教学角色

至少检查：

- 区分 education-learning 题与 career-work 中的教育职业；
- 知识输入／资格、讲授输出／培养、职业位置和现实结果接口中，哪些实际成立；
- 印、食伤或其他节点的功能、路线与日主调用权已经冻结；
- 已比较学习研究、专业资质、内容输出、培训教学与教育机构等替代载体。

甲的培育／生长性质、印的输入／承载或食伤的输出都只能贡献一部分；任何单项都不能直接推出教师或教育行业。

## 运行时位置与机器收据

领域载体不是另一张供模型自由联想的 Deep Card。运行顺序固定为：

```text
Topic Lens domain_carrier_request
→ Source Lookup 编译 candidate leads（最高 candidate）
→ Composition 读取冻结 process、selected units 与现实 gates
→ Domain Carrier Resolver 比较候选
→ finding／resonance map／render envelope
```

具体职业、岗位、正式身份、疾病或事件一旦进入 finding，必须产出 `domain-carrier-resolution-<topic>.json`。文件至少含：

- `schema_version: "2.0"`；旧 1.0–1.1 只读兼容
- `case_id`、`topic_id`、`structure_freeze_id`
- `topic_lens_ref`、`runtime_packet_ref`
- `runtime_context_policy_ref`：v1.1 必填；非 timing 可为 `not-applicable`
- `resolutions`

每项 resolution 至少含：

- `resolution_id`、`domain_request_ref`、`axis_id`、`judgment_dimension_refs`、`carrier_family`
- `specificity_verdicts`：L1–L5 分栏；每层记录 verdict、claim rank、support／gap 与是否进入 finding
- `resolution_status`：`candidate-only／resolved／source-gap／not-applicable`
- `candidate_pool`
- `selected_carrier_ids`

每个 candidate 至少含：

- `candidate_id`、`label`、`specificity_level`、`rank`：candidate／supported／preferred／assertable
- `source_lead_refs`
- `contributing_card_ids`：只作来源追踪，不计作独立结构证据
- `contribution_groups`：分别列 `process_or_work_property`、`relation_function`、`position_visibility_or_route`、`daymaster_access_and_sustainability`、`destination_and_external_result`
- `independent_anchor_refs`
- `passed_gates`、`blocked_or_missing_gates`
- `alternative_carrier_ids`、`comparison_reason`
- `single_symbol_card_sufficient: false`
- `assertable_fact_refs`：非 assertable 可为空
- `forbidden_direct_inferences`
- `relation_function_transition`：v1.1 必填；非 timing 写 `not-applicable`
- `retained_natal_route_ref`：v1.1 timing／synastry 必填
- `runtime_context_branches`：v1.1 必填
- `structural_impact_bounds_ref`：v1.1 timing／synastry 必填

每个 `runtime_context_branch` 至少含：

- `branch_id`
- `context_status`：`known-from-question`／`conditional`／`not-applicable`
- `position_or_role_condition`
- `carrier_expression`
- `agency_difference`
- `structural_claim_unchanged: true`
- `context_used_as_structure_evidence: false`

命主当时位置可改变“这个关系功能由谁承担”和“命主能处理到哪一段”，不得改写 process diff、原局剩余主路或结构置信度。位置未知且本载体依赖位置时，至少保留两个有意义的条件分支。

晋级规则：

- `candidate`：允许只有部分贡献，用于候选池，不进入主结论。
- `supported`：至少有过程／工作性质、关系功能、位置／可见接口或路线三类贡献，且至少两个独立 chart anchors；单张符号卡不能成为充分理由。
- `preferred`：在 supported 基础上必须比较至少一个替代载体，并说明为什么当前候选更贴合。
- `assertable`：除 preferred 条件外，必须有窄问题中的具体事实或多个独立事实锚点；不得只凭象意提高。

若 exact identity 只能 candidate／not-claimed，resolver 仍必须输出 L1–L4 已成立的 verdict。`resolution_status: candidate-only` 不能成为整题退回流程描述的理由。

### 学习—职业并行 gate

形成期遇财、官杀、食伤或印时，不得预设学习与工作互斥。必须比较普通在校、奖助／供给型教育、军校或单位培养、实习／临床／学徒、带薪训练、边学边做、取得资格后正式任职。只有结构与 timing 明确破坏学习路线且没有保留路径时，才把离校／中断列为主判断。

运行 `scripts/validate_domain_carrier_resolution.py`。该脚本只校验桥接层级和收据完整性，不替代命理判断。
