# 反例：问题闭环冒充断盘

以下写法即使字段齐全、每题超过八十字，也不算合格 Render：

```text
关于“命主适合做什么任务”，结论是：更适合流程、维护和收尾。
形成链是土生金，优势是能落地，代价是责任增加。条件是资源和权限到位。

关于“命主在组织里是什么角色”，结论是：更容易成为实务骨干。
形成链仍是土生金，优势是能落地，代价是责任增加。条件是资源和权限到位。

关于“命主怎样获得收入”，结论是：更容易靠专业交付获得收入。
形成链仍是土生金，优势是能落地，代价是责任增加。条件是资源和权限到位。
```

失败原因：

- 问题成为正文骨架，读者只能看到逐题填表；
- 三个答案共用同一机制，没有各自的十神链、柱位、干支组合和现实结果门；
- 载体结论可能在 Topic Lens 阶段已经预写，Source 与 Finding 只负责复制；
- “形成、优势、代价、条件”是标签，不是连续因果；
- 没有主象、次象、反转象与人生主线；
- 审计若只检查答案原句存在和字数，会把循环生成误判为 PASS。

正确处理：问题只进入覆盖与 receipt；正文围绕经审计的象核和人生主线展开，再由不可见 marker 证明每个真实用户问题已被回答。
